1. EXECUTIVE SUMMARY
================================================================================

This project started from a ChatGPT export (chatgpfile.txt) comparing POSH Act
requirements vs a commercial platform workflow. The goal became a fully operable
HTML/CSS/JS prototype named:

    ISARVA POSH Compliance Platform

It is NOT production HRMS code — it is a client-demo prototype with:
  - Sidebar navigation
  - localStorage persistence (browser)
  - Inline help on every screen (IC, conciliation, inquiry, etc.)
  - 9-step Operate Case wizard
  - Compliance checklist (Section 19 employer duties)
  - Audit log, IC setup, workshops, data export/import

You are planning to upload this into your HRMS application and integrate it.
This document captures the entire Cursor conversation context so developers
and HR/legal teams have one reference file.

7. IC AND LC — FULL FORMS
================================================================================

IC = Internal Committee
-----------------------
  Legal: POSH Act 2013, Section 4 + Rules
  Required when: Establishment has 10 or more employees
  Purpose: Receive complaints, conduct inquiry, recommend action to employer

  Composition:
    - Presiding Officer: senior-level woman employee
    - Minimum 2 other employee members
    - 1 External Member (NGO / legal-social background) — mandatory outsider
    - At least 50% women on committee
    - Tenure: typically 3 years
    - IC at each administrative unit with 10+ staff (or district grouping)

  In app: IC Setup menu + Operate Case when "Routed to: IC"


LC = Local Committee
--------------------
  Legal: Sections 6, 7 — district level via District Officer
  Required when:
    - Workplace has fewer than 10 workers (no IC), OR
    - Complaint is against the employer (conflict of interest for internal IC)

  In app: New Complaint → Respondent Type "Employer" or checkbox "against employer"
          → routed to LC. Operate steps still IC-style (LC-specific UI not built).

8. COMPLIANCE PAGE — MEANING AND BEHAVIOUR
================================================================================

WHAT "COMPLIANCE" MEANS
-----------------------
  Not one complaint case — organisation-level legal duties under POSH Act
  Section 19 (employer obligations) + Section 22 (annual report to government).

WHO USES IT
-----------
  HR / Management / Compliance officer / Employer representative
  NOT the complainant woman filing harassment case (she uses New Complaint + IC process)

EMPLOYER DUTIES (SECTION 19) CHECKLIST
--------------------------------------
  Stored in: data.employerDuties[] (14 items from EMPLOYER_DUTIES_S19)
  Examples:
    - Provide safe working environment
    - Display penal consequences at conspicuous place
    - Display IC constitution order
    - Organize awareness workshops
    - Orient IC members
    - Facilitate IC/LC proceedings
    - Assist witnesses attendance
    - Treat SH as misconduct in service rules
    - Annual report to District Officer
    - etc.

WHAT HAPPENS WHEN YOU TICK A CHECKBOX (PROTOTYPE)
-------------------------------------------------
  1. Item marked done in browser localStorage
  2. Line may show grey/strikethrough on Compliance page only
  3. Date stored when ticked
  4. Does NOT: post to government, put posters on walls, show on other pages

AWARENESS WORKSHOPS
-------------------
  Separate card on Compliance page — name + date → Add → list on same page
  Supports annual report evidence (training done)

REAL WORLD EXAMPLE
------------------
  HR displays IC order in canteen (real life)
  HR ticks "Display order constituting IC" in app (internal tracking)
  HR runs "POSH Q1 2026" workshop → adds in workshop list
  Year-end: annual report to District Officer uses case counts + workshops + duties

9. CRITICAL BUGS FOUND AND FIXED
================================================================================

  Cause:  element?.textContent = value  (invalid assignment syntax)
  Fix:    Safe DOM text setter in isarva-posh-app.js

11. HANDLING LAW CHANGES (RECOMMENDED FOR HRMS)
================================================================================

Current prototype: rules hardcoded in isarva-posh-data.js + isarva-posh-help.js

Production approach:
  1. Move duties, timelines, steps to versioned JSON (legal-config/posh-2013.json)
  2. Each rule: id, section, text, effectiveFrom, effectiveTo
  3. Organisation: legalPackVersion = "2028.1"
  4. Each case: applicableLegalVersion frozen at filing date
  5. Admin UI to publish new config — not developer edit for every amendment
  6. Audit log when legal pack changes
  7. Disclaimer: tool assists process; legal advice from company counsel

When Parliament amends POSH:
  - New complaints use new rules
  - Open cases usually keep rules at filing date (legal team decision)
  - Compliance checklist gets new rows from config

13. DATA MODEL (localStorage) FOR BACKEND MIGRATION
================================================================================

CASE STATUSES (STATUS_LIFECYCLE in isarva-posh-data.js):
  Draft, Submitted, Acknowledged, Under IC/LC Review, Additional Info Requested,
  Rejected (with reasons), Routed to LC, Conciliation*, Interim Relief Applied,
  Inquiry Started, Notice Issued, Hearing*, Recommendation*, IC Report Submitted,
  Management Action Pending, Action Implemented, Appeal*, Closed, Archived, etc.

STATUTORY TIMELINES (STATUTORY_TIMELINES):
  Complaint: 3 months + 3 extension (Section 9)
  Notice: 7 working days before hearing (Rule 6)
  Inquiry: 90 days (Section 11)
  IC report to employer: 10 days after inquiry end
  Management action: 60 days
  Appeal: 90 days (Section 12)
  Annual report: every calendar year (Section 22)

EMPLOYER DUTIES: EMPLOYER_DUTIES_S19 array (14 strings)
HARASSMENT TYPES: HARASSMENT_TYPES array
INTERIM RELIEF: INTERIM_RELIEF_OPTIONS array
